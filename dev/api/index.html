BIOMFormat.BIOMTable — Type
BIOMTable

A BIOM table: counts (or other values) of observations (OTUs, ASVs, genes, ...) in samples, with optional metadata on each.

  • id, type, generated_by, creation_date: the file's header. type is BIOM's controlled vocabulary, e.g. "OTU table".
  • observations, samples: the ids, in row and column order.
  • data: the values, a sparse observations × samples matrix (Int when every value is a whole number, else Float64).
  • observation_metadata, sample_metadata: one Dict{String,Any} per id, or nothing when the file has none. A lineage is stored as a vector of ranks under "taxonomy".
  • observation_group_metadata, sample_group_metadata: values describing a whole axis, e.g. a phylogeny, as name => (data_type, value).

Construct one with BIOMTable(data, observations, samples; kwargs...), or read one with read_biom.

BIOMFormat.read_biom — Method
read_biom(path) -> BIOMTable
read_biom(io::IO) -> BIOMTable

Read a BIOM table. Both BIOM 2.1 (HDF5, what QIIME 2 exports) and BIOM 1.0 (JSON) are read from a path, the format told from the file's first bytes; from an IO, only JSON.

source
BIOMFormat.write_biom — Method
write_biom(path, t::BIOMTable; format = :hdf5)
write_biom(io::IO, t::BIOMTable)

Write t as BIOM 2.1 (format = :hdf5, the default) or BIOM 1.0 (format = :json). An IO gets JSON. BIOM 1.0 has no group metadata, so a table with some warns that it is dropped.
